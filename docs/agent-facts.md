# Agent Facts

Verified environment facts and pitfalls. Add new ones here.

- **Python 3.13 only**: `requirements.txt` pins `audioop-lts` (3.13 backport). Venv must be `.venv/` (hard-coded in `manage_service.sh` and the server's PATH setup).
- **Port 7790 busy**: the launchd daemon holds it and the model in memory. `./manage_service.sh stop` before running the server in the foreground.
- **Code changes not taking effect**: the daemon keeps the old process; `./manage_service.sh restart`.
- **launchd EX_CONFIG (78)** happened when the repo lived on an external volume (chdir / log file open failed; Python needed removable-volume access). Fix was moving the repo to the internal disk; plist also omits `WorkingDirectory` and logs to `~/Library/Logs/speech-server/`.
- **STT fails with ffmpeg not found**: mlx-whisper shells out to `ffmpeg`; the server symlinks imageio-ffmpeg's versioned binary to `.venv/bin/ffmpeg` at startup. Check that `imageio-ffmpeg` is installed or `brew install ffmpeg`.
- **Tokenizer load error**: transformers 5.0.0rc3 needs `fix_mistral_regex=True` for the Qwen tokenizer; handled by `patch_transformers_tokenizer_loader()`.
- **Git push "did not receive expected object"**: repo was a shallow clone; `git fetch --unshallow upstream` fixed it.
- **SwiftBar icon color**: `sfcolor` is drawn as a template (white). Use `sfconfig` (base64 JSON, `renderingMode: Palette`, two colors: glyph then circle). SwiftBar runs plugins with a minimal PATH; use absolute binary paths. Refresh manually: `open -g swiftbar://refreshallplugins`.
- **First TTS call slow (6–15 s) after long idle**: not a bug. MLX's default wired limit is 0, so under memory pressure (16 GB Mac + other apps) macOS swaps the idle model's ~2.7 GB GPU buffers out; check with `vmmap -summary <pid> | grep 'IOAccelerator (graphics)'` (SWAPPED column). Fixed by `mx.set_wired_limit` at startup (`SPEECH_SERVER_WIRED_LIMIT_MB`). The limit is not a hard cap: a loaded STT model is wired too (~+2 GB) until it idle-unloads.
- **TTS speed ceiling at 1.7B-8bit**: talker forward is memory-bandwidth bound (~16 ms/token); only fewer bits would cut it, which the user rejected for quality. Sampling cost is negligible. Japanese-only use gives no speedup (codec vocab and compute are language-independent).
- **Opening words missing / first ~0.5–1.2 s silent or garbled (fixed)**: not the model and not text feeding. MLX 0.30.3's Metal `conv_transpose1d` returns wrong values at the start of any output longer than ~32768 frames (CPU and plain `conv1d` are fine); the codec decoder's last upsampling layer outputs 24 kHz audio, so every clip > ~1.36 s was hit (95% of logged requests). Damage length ≈ (samples − 32768) / 24000 s. Fixed by `mlx_fixes.apply()` (chunked transpose conv). Tried and disproven first: non-streaming prefill, appending 。, low-temperature retry, sampling/language/ref-audio/speaker changes. Moving only the conv to the CPU stream without `mx.eval` around it crashed the process with a Metal GPU Timeout. Audio generated before the fix (batch assets, grammar_example uploads) likely has damaged openings.
